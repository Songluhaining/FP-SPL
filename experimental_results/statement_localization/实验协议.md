# 修正假通过配置后的语句级缺陷定位实验

本轮预先登记全部 1054 个案例、32494 个配置和 16790 个原本通过配置。六系统单缺陷均进入清单，银行账户、电梯、邮件、考试数据库另含双、三缺陷。图处理和压缩系统多缺陷按用户要求暂缓。原始系统、报告、逐用例成败与覆盖只读，派生文件在原案例 .fp_research/statement_localization 内生成。

主方法使用当前联合贝叶斯版本，各案例独立推断。此前三个系统406个多缺陷案例的推断只有在源码、输入摘要和输出摘要均一致时复用，其他案例补跑当前版本。两种公开基线在各系统、各缺陷层按版本固定五折预测，监督方法仅使用训练折标签，正例学习同时保留此前等量抽样和源码默认5%设置。缺分配置保留，不能用评价真值补全预测。

语句级定位调用用户指定的 VARCOP 仓库，固定提交 62b413b52bbfba1f86a244ddb9f1daed232e329e。本地源码快照见 fp_research/vendor/varcop，兼容和只读路径适配在外层实现。特征切片程序与官方版本逐字节相同。主指标选 Ochiai，另报 Tarantula、Op2、Barinel、Dstar 和 Jaccard，统一使用默认0.5权重、局部分数归一化及算术平均聚合。覆盖过滤固定为0以保留全部可用原始产品。

修正按公开分类比较入口的方式进行，将预测为假通过的原本通过配置从 VARCOP 的通过证据中排除，保留可见失败产品和它们的原测试。未修正、联合方法修正、监督分类修正及正例学习两种设置使用相同定位参数。每次修正后重新生成可疑特征组合和特征切片，完整重新计算产品级分数与定位次序。筛选开关沿用官方入口仅检查Base（压缩系统另含Compress）选项的原始规则，不改写BankAccount、ExamDB等原特征名；明细保存实际开关值，并另存完整与筛选排名供核查。

排名保存后才读取注入日志。每个注入位置单列，报告最坏并列名次、Hit@1/3/5/10、固定原始系统语句分母下的EXAM、每案例首故障与全部故障检查量，以及相对未修正的改善、相同和退化数。重复注入同一语句时按唯一源码位置计数。未出现在候选排名的故障位置保留未定位标记，不能丢弃或记成负数好成绩。评价明细与原始排名分别归档，独立脚本重算所有统计。

先在小图和真实代表案例核验后扩展完整范围。六个模型小图及分折检查通过，首个银行账户案例的六种完整排名和隔离排名与官方完整定位入口逐值一致。每个阶段逐案例记录完成或失败原因，只有清单全部完成并通过核验才生成完成凭据。

为控制运行成本，可疑特征组合使用等价的最小击中集计算，保留官方七个特征选择上限与输出次序；80组随机小样例与原始穷举逐行一致。同一产品的依赖图及静态关系按源码、失败覆盖和工具摘要缓存，保留官方语句切片和字段传播函数，每份新缓存均与官方交互计算函数逐项比较后才发布。六系统各一个完整案例的特征切片集合、六种完整和筛选定位分数及名次均与未改动的官方程序核对；不参与官方定位的交互计数如有差异另行记录，不将其误称为完全逐值一致。并列层内语句顺序不影响最坏并列名次，核验比较每条分数、并列层次和最终名次。正式运行的特征遍历种子固定为42，登记发生于正式定位评分之前。

## 复现与恢复

以下命令在本机仓库根目录运行，数据路径见 `fp_research/dataset_locations.json`。需要保留同级目录中的两种比较方法源码与切片程序，实际软件版本由结果目录的 `software.json` 保存。原案例中的 `.fp_research` 是派生缓存，原始数据不参与写入。

```powershell
Set-Location 'E:\Myself\投稿\work7\BRFL'
$researchPython = 'D:\SoftInstall\python.exe'
$env:PYTHONUTF8 = '1'
$env:PYTHONHASHSEED = '42'
$env:MKL_NUM_THREADS = '1'
$env:OMP_NUM_THREADS = '1'
$env:OPENBLAS_NUM_THREADS = '1'
$env:NUMEXPR_NUM_THREADS = '1'
$env:FP_SLICE_BACKEND = 'indexed'
$env:FP_SLICE_WORKERS = '2'
& $researchPython -m fp_research.varcop_source
& $researchPython -m fp_research.localization_study manifest
& $researchPython -m fp_research.localization_study fit --workers 6
& $researchPython -m fp_research.localization_study prepare --workers 3
& $researchPython -m fp_research.checks.localization_feature_check
& $researchPython -m fp_research.localization_study classify --method CLAP
& $researchPython -m fp_research.localization_study classify --method PULP
& $researchPython -m fp_research.localization_study classify --method PULP --original-default
foreach ($researchSystem in 'bank','elevator','email','examdb','gpl','zipme') {
    & $researchPython -m fp_research.checks.localization_smoke --system $researchSystem
    if ($LASTEXITCODE -ne 0) { throw "代表案例核验失败：$researchSystem" }
}
& $researchPython -m fp_research.checks.localization_slice_check
& $researchPython -m fp_research.localization_study rank --workers 4
& $researchPython -m fp_research.localization_study evaluate
& $researchPython -m fp_research.checks.verify_localization
```

此前406个多缺陷推断缓存如被移除，先运行 `python -m fp_research.multifault_study fit --workers 6` 重建，再执行本轮 `fit`。运行中的分类按折保存，定位按案例保存；重跑入口会先核对输入、源码和产物摘要，再复用一致的结果。仅修复一个案例可在 `fit`、`prepare`、`rank` 后增加 `--system bank --stratum 2 --version _MultipleBugs_.NOB_2.ID_41` 等筛选参数，修复后仍需运行完整汇总和独立核验。

本轮为缩短等待，已就绪折可用 `python -m fp_research.localization_rank_stream` 同时进行定位；它与完整入口调用相同的逐案例函数，以固定单折预测作为不可变输入，不改变任何参数或评价分母。最终完整入口仍逐项确认全部案例，统计只在全量排名完成后产生。15项检查包含80组穷举对照和四进程文件锁核验，命令为 `python -m unittest fp_research.checks.test_localization fp_research.checks.test_varcop_spcs fp_research.checks.test_varcop_slice fp_research.checks.test_joint_fault fp_research.checks.test_multifault_partitions`。
