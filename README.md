# FP-SPL：基于反事实测试与因果推理的假通过识别

本仓库实现一种面向软件产品线的证据分级方法。它不使用真假通过研究标签训练模型，也不沿用旧版的正样本与无标签学习、程序切片或图神经网络流程。配置报告中的“未通过”只用于寻找已知故障行为，“通过”配置是待检查对象。

人工审查请先读[代码阅读指南](docs/code-reading-guide.md)。运行入口是`cfp_spl/__main__.py`，参数入口是`cfp_spl/cli.py`的`main()`，主算法流程在`cfp_spl/pipeline.py`的`_run_version()`。

## 方法定义

对每个原本通过的配置A执行以下步骤：

1. 将特征选择表示为0/1向量，在所有未通过配置中按欧式距离寻找最近的配置B。对二值向量，该距离等于不同特征数量的平方根。输出同时保留差异特征，便于解释近邻为何被选中。
2. 读取B的失败测试，规则匹配完全一致测试；其他配对让DeepSeek从相似候选中按输入场景、被测行为和判定目标选择。
3. 无可靠候选时生成JUnit测试，进行独立语义复核、两侧编译执行与轨迹检查，最多三轮反馈修复。只满足断言文本相似不足以证明反事实可比性。
4. 像BRFL一样用`javac -g`重编译，保留字节码到源码行的映射；用随仓库保存的BRFL代理进行字节码插桩，采集静态语句日志与逐指令运行日志。
5. 每次执行先用BRFL解析依赖结构，不计算单侧后验。将同一A的全部有效A/B执行合入统一因子图：按特征源码身份共享语句节点，每次执行的值节点和依赖因子独立保留。未映射语句不跨执行合并。之后只运行一次循环信念传播。
6. 使用统一图的语句可疑度，即1减正确后验概率；要求相关特征语句处于A/B共同执行的结果依赖路径。移除旧A/B后验差值规则。轨迹完全不相干时尝试生成替代测试，并记录原匹配失败原因。
7. 经语义和执行验证的生成测试在A中断言失败时记为确认假通过；A通过时按共同语句的最高可疑度排序，默认0.55作为疑似阈值。阈值尚未校准，不代表配置缺陷概率。

因此，“可疑语句的源码也存在于A”只是必要条件，不是最终判据。这样可以排除未执行代码、与测试结果无关的代码，以及A、B两侧同样可疑但没有掩蔽差异的语句。

## 证据等级

| 等级 | 判据 |
|---|---|
| 确认假通过 | 经验证的反事实测试在A上失败，说明原测试套件漏检 |
| 强疑似 | 有效配对在A上通过，统一图中A/B共同结果路径语句可疑度至少0.55 |
| 弱疑似 | 兼容旧实验输出等级；当前统一图流程不产生此等级 |
| 证据不足 | 无有效反事实测试，或只有源码存在而没有执行、因果路径和后验差异证据 |

输出分数用于同一缺陷版本内排序，不解释为经过校准的概率。

## 运行

先只生成配置和测试配对计划，检查近邻与测试匹配是否合理：

```powershell
python -m cfp_spl `
  --dataset D:\dataset\whn\4wise-BankAccountTP-1BUG-Full `
  --version _MultipleBugs_.NOB_1.ID_98 `
  --java-home 'E:\Program Files\Java\jdk-1.8' `
  --output E:\Myself\投稿\work7\FP-SPL\outputs\counterfactual `
  --plan-only
```

去掉`--plan-only`后执行重编译、插桩、测试和因果推理。默认每个A选择所有并列最近的B；`--neighbors 3`至少保留前三个近邻，并保留第三个近邻距离上的全部并列项。最终排名记录支持配对数量。

### 接入测试生成模型

程序可以直接调用DeepSeek。接口密钥默认依次从`DEEPSEEK_API_KEY`环境变量、`--deepseek-api-key-file`指定文件，以及仓库同级的`deepseek-api-key.txt`读取。密钥文件已被版本控制忽略。

```powershell
python -m cfp_spl ... `
  --deepseek-api-key-file E:\Myself\投稿\work7\deepseek-api-key.txt `
  --deepseek-model deepseek-chat
```

模型选择阶段发送失败测试、A中相似度最高的至多12个候选测试以及A/B差异特征；生成阶段还发送A/B产品源码。响应缓存按请求内容、模型、接口和协议版本摘要区分。生成测试最多经过三轮结构检查、真实编译执行和诊断反馈修复；每轮请求、响应和验证报告均保留。由于这些内容会发送给外部服务，正式实验前需要确认数据允许这样使用。

生成测试不得输出空断言、恒真断言或跳过测试。非机械复制的测试必须通过独立语义复核，保持故障判定目标；B必须因断言失败复现故障，A的普通运行异常不作为确认假通过。编译执行和模型复核不能证明完全等价，正式使用仍需检查输入、断言及失败位置。`--plan-only`不进行真实验证，生成测试不能直接视为有效证据。

模型输出不能直接成为识别结果。选择出的已有测试必须在A上通过、在B上失败；生成测试也必须在两侧成功编译，并在B上复现故障。若生成测试在A上同样失败，则它直接揭示了原测试套件遗漏的故障行为；此时不要求先成功构建概率因子图。

也可以通过外部命令接入其他模型。`--generator-command`接受一个外部命令，其中可使用`{request}`和`{response}`占位符。程序将请求写成JSON；外部程序需要把结果写入指定响应文件。示例：

```powershell
python -m cfp_spl ... `
  --generator-command 'python my_generator.py --request {request} --response {response}'
```

外部命令接口不绑定某个模型或网络服务。请求中包含A/B的差异特征、B的失败测试完整源码、测试内容和判定条件；响应必须包含完整Java源码、类名、方法名和生成理由。生成代码仍要经过两个配置上的真实编译与执行验证，模型文字说明不能替代验证。

## 输出

- `pair-plan.json`：A/B距离、差异特征、失败测试、反事实测试及匹配强度。
- `generation-requests/`：无法从A找到对应测试时的结构化生成请求和响应。
- `configurations/<配置>/build/`：带调试行号信息的重编译产物。
- `runs/<执行摘要>/graph/factor-graph.tsv`：单次执行的依赖结构和因子表；未执行单侧推理。
- `joint/<配置>/joint-factor-graph.tsv`：共享语句节点、独立动态值节点及统一后验。
- `pair-assessments.json`：逐A/B/测试配对的因果证据和证据等级。
- `ranking.csv`：配置级最终排序；保留最佳证据及支持配对数量。
- `errors.json`：编译、结果复现、插桩或推理失败，不会被静默当成阴性样本。

## 过程验证

每个统一图检查静态语句身份唯一、动态值独立以及通过/失败观测共存。逐配对记录语句覆盖与结果路径的交并比；没有共同结果路径时不当作有效反事实证据。完整日志位置和人工阅读顺序见[代码阅读指南](docs/code-reading-guide.md)。

## 实现边界

- 相似测试不自动等价于反事实测试。代码把它降为较弱证据，并完整输出相似度与判定条件相似度供人工核查。
- 如果A和B的接口差异太大，生成测试可能无法在两侧同时编译；这会记为证据不足。
- BRFL给出的后验概率依赖插桩轨迹、观测点和参数设置。统一图只提供模型假设下的后验，不能假设单次推理必然准确。
- 基础特征中的缺陷不会被跳过。只要反事实测试能激活相关语句并产生可观察差异，它与可选特征中的缺陷使用相同流程。

`vendor/brfl/`保存了从原BRFL仓库移植的重编译、插桩和因子图实现；运行不会修改原BRFL仓库或原始数据集。

## 完整数据集评价

主实验统一只评价原始测试结果为通过的配置，在这些候选中识别真通过和假通过。由失败配置人工改标得到的假通过不进入主实验；这类样本只在补充实验中单独评价。完整口径与指标约束见[评价规范](docs/evaluation-protocol.md)。

可将73个缺陷版本拆成多个互不重叠的运行分片：

```powershell
python -m cfp_spl.batch --dataset <数据集> --output <结果目录> `
  --java-home <Java8目录> --shards 4 --index 0
```

分别将`--index`设为0、1、2、3并行运行。完成后执行：

```powershell
python -m cfp_spl.evaluation --results <结果目录> --labels <标签目录>
python -m cfp_spl.diagnostics --results <结果目录> --labels <标签目录>
python -m cfp_spl.ablation --results <结果目录> --labels <标签目录>
```

评价程序只在全部排序完成后读取真假通过标签。完整BankAccountTP实验结果和限制见[实验报告](docs/experiment-bankaccount-all73.md)，Email单缺陷数据的阶段性结果见[Email实验报告](docs/experiment-email-1bug.md)。
