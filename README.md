# FP-SPL：基于反事实测试与因果推理的假通过识别

本仓库实现一种面向软件产品线的证据分级方法。它不使用真假通过研究标签训练模型，也不沿用旧版的正样本与无标签学习、程序切片或图神经网络流程。配置报告中的“未通过”只用于寻找已知故障行为，“通过”配置是待检查对象。

## 方法定义

对每个原本通过的配置A执行以下步骤：

1. 将特征选择表示为0/1向量，在所有未通过配置中按欧式距离寻找最近的配置B。对二值向量，该距离等于不同特征数量的平方根。输出同时保留差异特征，便于解释近邻为何被选中。
2. 读取B的每条失败测试，在A的测试源码中寻找内容与判定条件均相近的测试。完全一致的测试标为“严格配对”，相似测试必须同时通过内容相似度和判定条件相似度门槛。
3. 找不到已有测试时，直接调用DeepSeek生成完整的JUnit反事实测试。请求同时包含A、B的产品源码、差异特征、B的失败测试及判定条件；生成结果经过结构校验，并分别在A和B上真实编译、执行。只有在B上复现失败后才进入因果分析。也可通过外部命令换用其他模型。
4. 像BRFL一样用`javac -g`重编译，保留字节码到源码行的映射；用随仓库保存的BRFL代理进行字节码插桩，采集静态语句日志与逐指令运行日志。
5. 分别从A的通过执行和B的失败执行导出BRFL运行值子图，但不对任何单次执行独立推理。优先用原始特征源码位置对齐语句；A、B中对齐的语句合并为同一个正确性变量，各自的运行值、定义使用关系和测试结果仍保持独立。由此形成一张同时含通过与失败证据的联合反事实因子图。
6. 从已有覆盖报告计算共享语句的频谱先验，再对整张联合图进行一次自适应区域张量推理。在区域变量上限内建立团树并得到精确边缘后验；超过上限时使用有界区域消息传递。语句可疑度定义为`1－共享语句正确性的联合后验概率`。
7. 如果反事实测试直接在A上失败，则确认A是假通过；如果A仍通过，则使用联合图中同时在A、B执行且位于B失败结果因果路径上的高可疑共享语句对A排序。

反事实配置和测试配对的作用，是为同一共享语句同时提供A侧通过约束和B侧失败约束。没有这一步，联合概率模型无法区分正常执行与故障执行。

## 证据等级

| 等级 | 判据 |
|---|---|
| 确认假通过 | 经验证的反事实测试在A上失败，说明原测试套件漏检 |
| 强疑似 | 联合图中存在同时受A通过执行和B失败执行约束的高可疑共享语句 |
| 弱疑似 | 保留用于兼容旧实验输出；联合图新流程不使用该等级 |
| 证据不足 | 无有效反事实测试，或联合图中不存在达到阈值的共享故障因果语句 |

输出分数用于同一缺陷版本内排序，不解释为经过校准的概率。

## 运行

先只生成配置和测试配对计划，检查近邻与测试匹配是否合理：

```powershell
python -m cfp_spl `
  --dataset D:\dataset\whn\4wise-BankAccountTP-1BUG-Full `
  --version _MultipleBugs_.NOB_1.ID_98 `
  --java-home 'E:\Program Files\Java\jdk-1.8' `
  --output E:\Myself\投稿\work7\FP-SPL\outputs\counterfactual `
  --plan-only
```

去掉`--plan-only`后执行重编译、插桩、测试和因果推理。默认每个A只使用一个最近的B；为了降低单个近邻选择错误的风险，可以用`--neighbors 3`检查多个等距或近距故障配置，最终排名会记录支持该结论的配对数量。

默认使用自适应区域张量推理。`--max-region-variables 14`控制单个精确区域的最大二值变量数；`--spectrum-metric ensemble`使用多频谱指标中位数。旧版循环信念传播只能作为历史单配置实现复现，不能直接用于当前跨配置联合图。

### 生成反事实测试

程序按以下顺序寻找DeepSeek接口密钥：环境变量`DEEPSEEK_API_KEY`、`--deepseek-api-key-file`指定的文件、环境变量`DEEPSEEK_API_KEY_FILE`指定的文件、仓库同级的`deepseek-api-key.txt`。当前工作区中的`E:\Myself\投稿\work7\deepseek-api-key.txt`会被自动发现，无需把密钥复制进仓库。密钥不会写入请求、响应或日志；仓库也会忽略所有名称包含`api-key`的文本文件。

默认调用`https://api.deepseek.com/chat/completions`，使用`deepseek-flash`和JSON结构化输出。可显式指定：

```powershell
python -m cfp_spl ... `
  --deepseek-api-key-file E:\Myself\投稿\work7\deepseek-api-key.txt `
  --deepseek-model deepseek-flash
```

模型生成不是判定依据。生成源码必须在A、B两侧通过Java 8编译，并且在B上复现原故障；若在A上也失败，则形成直接的漏测证据。调用失败、响应格式错误、编译失败或无法在B上复现都会明确写入输出，不会当作有效测试。

### 换用外部生成程序

`--generator-command`接受一个外部命令，其中可使用`{request}`和`{response}`占位符。程序将请求写成JSON；外部程序需要把结果写入指定响应文件。示例：

```powershell
python -m cfp_spl ... `
  --generator-command 'python my_generator.py --request {request} --response {response}'
```

外部程序的响应必须包含完整Java源码、类名、方法名和生成理由。此入口优先于内置DeepSeek调用，生成代码仍要经过两个配置上的真实编译与执行验证。

## A和B如何形成一张联合图

A和B是不同编译产物，因此两次执行产生的运行值节点不能合并。代码只合并能够按原始特征源码位置和行内语句顺序对齐的“语句是否正确”变量。A、B各自的运行值节点、因子节点和测试结果观测连接到该共享变量。无法对齐的语句保留为单侧变量，不会被误当作共同语句。

这与BRFL处理多条测试轨迹的原则一致：测试特有的运行状态相互独立，程序语句的正确性跨测试共享。概率推理只在联合完成后执行一次。

## 输出

- `pair-plan.json`：A/B距离、差异特征、失败测试、反事实测试及匹配强度。
- `generation-requests/`：无法从A找到对应测试时的结构化生成请求和响应。
- `configurations/<配置>/build/`：带调试行号信息的重编译产物。
- `runs/<类>/<方法>/factor-graph.tsv`：单次执行的原始因子子图，仅用于随后构建联合图，不含最终推理结论。
- `joint-runs/<A>/<B>/<配对>/tensor-inference.json`：联合图实际选择的张量推理路径、消元宽度、区域数量与收敛信息。
- `joint-runs/<A>/<B>/<配对>/tensor-posteriors.tsv`：共享语句的执行侧、频谱先验和联合后验。
- `spectrum-priors/<配置>.json`：从已有通过/失败覆盖报告计算的语句级频谱证据。
- `pair-assessments.json`：逐A/B/测试配对的因果证据和证据等级。
- `ranking.csv`：配置级最终排序；保留最佳证据及支持配对数量。
- `errors.json`：编译、结果复现、插桩或推理失败，不会被静默当成阴性样本。

## 对因果推理可靠性的优化

当前方法的两个核心点是：用反事实配对构建同时含通过与失败约束的联合动态因子图；用频谱先验和区域张量消息计算共享语句的错误后验。正式实验可消融频谱先验以及A侧通过轨迹，直接验证两部分贡献。

这样可以直接验证每个约束对误报率的影响。后续还可以针对BRFL的`infer.txt`使用多组先验参数重复推理，只保留跨参数稳定出现的语句；当前导出格式已经保留完整因子参数表，支持该扩展。

## 实现边界

- 相似测试不自动等价于反事实测试。代码把它降为较弱证据，并完整输出相似度与判定条件相似度供人工核查。
- 如果A和B的接口差异太大，生成测试可能无法在两侧同时编译；这会记为证据不足。
- BRFL给出的后验概率依赖插桩轨迹、观测点和参数设置。方法通过差分证据降低绝对概率误差，但不能假设单次推理必然准确。
- 基础特征中的缺陷不会被跳过。只要反事实测试能激活相关语句并产生可观察差异，它与可选特征中的缺陷使用相同流程。

`vendor/brfl/`保存了从原BRFL仓库移植的重编译、插桩和因子图实现；运行不会修改原BRFL仓库或原始数据集。

自适应区域张量推理的公式、区域构造、图宽测量和初步结果见[设计与初步验证](docs/adaptive-region-tensor-inference.md)。

## 完整数据集评价

可将73个缺陷版本拆成多个互不重叠的运行分片：

```powershell
python -m cfp_spl.batch --dataset <数据集> --output <结果目录> `
  --java-home <Java8目录> --shards 4 --index 0
```

分别将`--index`设为0、1、2、3并行运行。完成后执行：

```powershell
python -m cfp_spl.evaluation --results <结果目录> --labels <标签目录>
python -m cfp_spl.diagnostics --results <结果目录> --labels <标签目录>
python -m cfp_spl.ablation --results <结果目录> --labels <标签目录>
```

评价程序只在全部排序完成后读取真假通过标签。完整BankAccountTP实验结果和限制见[实验报告](docs/experiment-bankaccount-all73.md)。
